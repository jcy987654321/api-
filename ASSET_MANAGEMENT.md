# Asset Management Documentation

## Overview

This project uses Vite as the frontend asset pipeline to bundle, optimize, and serve JavaScript, CSS, and other static assets. All assets are hosted locally without relying on CDN services.

## Quick Start

### Development Mode

```bash
# Install dependencies
npm install

# Start Vite dev server with hot module replacement (HMR)
npm run dev
```

### Production Build

```bash
# Build optimized assets for production
npm run build
```

The build process will:
- Bundle and minify all JavaScript and CSS
- Generate hashed filenames for cache busting
- Output files to `public/build/`
- Create a `manifest.json` for asset mapping
- Split code into optimized chunks
- Add polyfills for legacy browser support

### Preview Build

```bash
# Preview production build locally
npm run preview
```


## Adding New Assets

### Adding JavaScript Modules

1. Create a new file in `resources/js/`:
   ```javascript
   // resources/js/my-feature.js
   export function myFunction() {
     // Your code here
   }
   
   export default {
     init() {
       // Initialization code
     }
   };
   ```

2. Import it in `app.js` or use lazy loading:
   ```javascript
   // Immediate loading
   import MyFeature from './my-feature';
   MyFeature.init();
   
   // Lazy loading (recommended for heavy modules)
   window.loadMyFeature = () => import('./my-feature');
   ```

3. For lazy-loaded modules, trigger loading when needed:
   ```javascript
   // In your application
   document.getElementById('feature-button').addEventListener('click', async () => {
     const module = await window.loadMyFeature();
     module.default.init();
   });
   ```

### Adding Styles

1. Create a new SCSS partial in `resources/scss/public/`:
   ```scss
   // resources/scss/public/_my-component.scss
   .my-component {
     // Your styles here
   }
   ```

2. Import it in `styles.scss`:
   ```scss
   @import 'my-component';
   ```

### Adding Images

1. Place images in `resources/images/`
2. Reference them in your code:
   ```javascript
   import logo from '@images/logo.png';
   ```
   ```scss
   .logo {
     background-image: url('@images/logo.png');
   }
   ```

3. For responsive images with WebP fallback:
   ```html
   <picture>
     <source srcset="{{ asset('build/images/hero.webp') }}" type="image/webp">
     <img src="{{ asset('build/images/hero.jpg') }}" alt="Hero image">
   </picture>
   ```

## Code Splitting Strategy

Heavy modules are lazy-loaded to minimize initial payload:

### Chart.js (Heavy: ~200KB)
```javascript
// Lazy load when needed
const chartModule = await window.initCharts();
const chart = chartModule.createChart('myChart', config);
```

### Syntax Highlighter (Heavy: ~100KB)
```javascript
// Lazy load for code blocks
const highlighter = await window.initSyntaxHighlighter();
highlighter.initSyntaxHighlighting();
```

### Media Preview (Medium: ~20KB)
```javascript
// Lazy load for image galleries
const preview = await window.initMediaPreview();
preview.init();
```

## Performance Optimizations

### Cache Busting
All assets have hashed filenames (e.g., `app-abc123.js`) that change when content changes, enabling long-term caching:
```
Cache-Control: public, max-age=31536000, immutable
```

### Compression
Assets are automatically compressed using gzip:
- Files > 10KB are compressed
- `.gz` files are generated alongside originals
- Configure your web server to serve `.gz` files when available

### Code Splitting
- Vendor libraries bundled separately
- Chart.js in separate chunk
- Prism.js in separate chunk
- Each chunk is cached independently

### Asset Inlining
- Small assets (< 4KB) are inlined as base64
- Reduces HTTP requests for tiny files

## CSS Management

### PostCSS & Autoprefixer
CSS is automatically prefixed for browser compatibility:
```scss
// You write:
.box {
  display: flex;
}

// Autoprefixer outputs:
.box {
  display: -webkit-box;
  display: -ms-flexbox;
  display: flex;
}
```

### SCSS Variables
Common variables are available in all SCSS files:
```scss
// Automatically imported
$primary-color: #007bff;
$spacing-md: 1rem;

.my-component {
  color: $primary-color;
  padding: $spacing-md;
}
```

## Coding Standards

### JavaScript

1. **Use ES6+ features**:
   ```javascript
   const items = [1, 2, 3];
   const doubled = items.map(x => x * 2);
   ```

2. **Use async/await for promises**:
   ```javascript
   async function loadData() {
     const response = await fetch('/api/data');
     return await response.json();
   }
   ```

3. **Destructure imports**:
   ```javascript
   import { Chart } from 'chart.js';
   ```

4. **Export clearly**:
   ```javascript
   export function helperFunction() { }
   export default MainClass;
   ```

### SCSS

1. **Use nesting sparingly** (max 3 levels):
   ```scss
   .component {
     .header {
       .title { }  // Max depth
     }
   }
   ```

2. **Use variables for repeated values**:
   ```scss
   $border-radius: 4px;
   
   .card {
     border-radius: $border-radius;
   }
   ```

3. **Use BEM methodology for class names**:
   ```scss
   .card { }
   .card__header { }
   .card__body { }
   .card--featured { }
   ```

4. **Mobile-first media queries**:
   ```scss
   .element {
     width: 100%;
     
     @media (min-width: 768px) {
       width: 50%;
     }
   }
   ```

## Troubleshooting

### "Module not found" errors
```bash
# Clear node_modules and reinstall
rm -rf node_modules package-lock.json
npm install
```

### Vite dev server not starting
```bash
# Check if port 5173 is available
lsof -ti:5173 | xargs kill -9

# Start server
npm run dev
```

### Build fails with memory error
```bash
# Increase Node memory limit
NODE_OPTIONS="--max-old-space-size=4096" npm run build
```

### Assets not loading in production
1. Ensure `npm run build` has been run
2. Check that `public/build/manifest.json` exists
3. Verify file permissions on `public/build/` directory
4. Clear browser cache

### HMR not working
1. Check that Vite dev server is running
2. Ensure `@vite` directive is in your layout
3. Try hard refresh (Ctrl+Shift+R)
